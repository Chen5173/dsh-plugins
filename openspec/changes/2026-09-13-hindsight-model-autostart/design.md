## Context

动机与范围见 `proposal.md`（Why / What Changes），此处只记影响做法的现状与约束。

**已经有的（本次复用，不重造）**

- 启停链路：`daemonAction('start'|'stop'|'restart')`（单飞、确认门、超时、回执）、`sanitizedEnv()` 环境净化、`/health` 探针、`POST /__hindsight-model/daemon`、面板「守护进程」区块（状态行 + 四个按钮）。实测停止 234ms、冷启动 46s。
- 停止路径的安全语义：先取监听端口 PID → 校验命令行含 `hindsight_api.main` + `--daemon` + 端口匹配 → 才终止。启动路径始终是官方 CLI：`uv run --directory "<embedPackagePath>" hindsight-embed daemon --profile <daemonProfile> start`，**从不调用 `profile create`**。
- 2026-09-13 的环境级修复：`.venv\Scripts\pythonw.exe` 已从 uv 的控制台 launcher 换成同一 3.12 发行版的 GUI 版（原件备份为 `pythonw.exe.uv-orig-<ts>`），daemon 因此不再分配控制台。

**宿主侧现状（决定怎么接自动启动）**

- 插件宿主半 `inject = []`、全部懒取 + 缺失降级，不 import 任何 `@deepseek-ai/*`。
- 官方 `hindsight` 行在宿主半用的钩子是 `ctx.on("agent/session-start", …)` 与 `ctx.on("agent/pre-step", …, { prepend: true })`——同类宿主能力本插件也可用，但**没有稳定的存在性探测手段**，只能「注册了等它派发」。

**本次实验得到的约束（proposal Why 的证据，这里只记结论）**

- 官方自动拉起在本机不生效，且解锁它的代价是「闪一个控制台」+「外层 env 成为会赢的一方」。
- 官方与我们在**同一个 `/health`** 上做去重：它已拉起时，本插件只要探测通过就直接采纳。

## Goals / Non-Goals

**Goals:**

- 会话要用记忆时守护进程**已经在跑**；没有则**后台**拉起，不阻塞会话。
- 采纳优先：已经在跑就**不重启、不写文件、不改动进程标识**。
- 失败**退避**且可见；用户能一键关掉自动启动。
- 启动前把「会分配控制台的启动器」自动换回无控制台版本，并把这次替换**如实报告**。
- 面板能看出守护进程**是谁拉起的**、以及它**有没有窗口风险**。

**Non-Goals:**

- 开机自启 / Windows 服务 / 任务计划。
- 改 `~/.hindsight/coding-agent.json`、动官方 `hindsight` 行、给上游包打补丁。
- 多 profile 切换、崩溃重启监护、复刻上游 `detectLlm()` 判定。
- 改变手动启停、四层对照、行级写入、HKCU 清理的既有行为。

## Decisions

### D1 触发点：订阅会话生命周期事件，缺失即降级

用宿主半的**会话开始事件**`agent/session-start` 作为触发；每次触发只做「一次健康探测 + 必要时一次后台启动」，不做常驻定时器。

- **实现期修订**：`agent/pre-step` **不用**。它与 `session-start` 不同，是插在每步之前的中介件（listener 形如 `(payload, next)`），注册错的签名会拖垮整条链路；而 `session-start` 是普通事件，签名无风险，且已经覆盖规格里「会话开始时确保可用」这一半。规格的措辞是「会话开始、**或**某个回合首次需要长期记忆时」，只接普通事件即满足。

- 备选一：`apply()` 时直接启动。否决——每次 DSH 重启都白付一次 44–73s 冷启动，且与「按需」语义不符。
- 备选二：定时轮询。否决——常驻开销，且退避逻辑要自己维护一套时间轴。
- **可见性补丁**：没有稳定的「事件是否存在」探测手段，所以记录「是否触发过」，面板把「自动启动：从未被触发」如实显示出来，避免静默失效。

### D2 采纳优先：先探 `/health`，通过就什么都不做

探测（2s 超时）通过 ⇒ 直接采纳：不重启、不写文件、不记录状态到磁盘，只在内存里记「本次来源＝外部」。只有探测不通过才启动。

- 备选：无条件重启。否决——会打断进行中的记忆操作，且每次都换 PID，与官方「already on the port is adopted, never restarted」相悖。

### D3 后台冷启动 + 退避

启动不 await 到就绪再放行会话（冷启动 44–73s）；失败按档位退避（建议 1min → 5min → 15min → 30min 封顶，成功即复位），且同一失败不重复产出提示。

- 备选：每回合都试。否决——失败时会反复 spawn 进程。
- 备选：一生只试一次。否决——一次失败后永不恢复。

### D4 launcher 自愈：只换那一个文件，先备份，失败就停

判定用**启动器文件自身的可执行文件头**（子系统类型）：控制台形态 ⇒ 用同一解释器发行版里的无控制台版本覆盖它；替换前备份原件到 `.venv` **之外**（避免 uv 重建 venv 时被清掉）。

- 备选一：重建整个 venv。否决——1.6GB / 431 个依赖要重装，且该 venv 由 hindsight-embed 自建，升级时可能又变回原样。
- 备选二：改上游第一跳的创建标志。否决——要给第三方包打补丁，升级即失效。
- 备选三：只把窗口藏起来。否决——误关窗口等于杀进程。
- **保守边界**：判定不出来（非 Windows、文件缺失、头不可解析）⇒ **不替换**，照原样启动并如实标注；替换失败 ⇒ 不启动并报告，不留半换状态。

### D5 来源判定：用监听进程的可观测证据，不写标记文件

判定链：监听端口的 PID → 该进程的镜像路径 + 父子关系；结合内存里「本进程这次动作」的记录，归纳为 **自动 / 手动 / 外部 / 未知** 四态；镜像属于会分配控制台的形态时追加「有控制台窗口风险」标注。

- 备选：写一个「谁拉起的」标记文件。否决——多一份会腐化的真源，且重启宿主后与事实脱节。

### D6 开关：`dsh-hindsight-model.autoStart`，默认开

在本插件**自己的** settings 命名空间（`hindsight-model`）注册一个布尔键 `autoStart`，默认**开**（本变更的目的就是让它自动发生），面板可关；关掉即回到今天的手动语义。

- **实现期修订**：本插件此前**没有** settings 命名空间，所以这是新注册一个（照抄兄弟插件 `dsh-esc-rewind` 的做法：宿主半动态 import `@deepseek-ai/schemastery`，拿不到时用零依赖的 fallback schema **也要把命名空间注册上**，否则面板的写入会被拒成「namespace is not registered」）；写路径经本插件自己的 `POST /__hindsight-model/auto` 落到同一个键，因此 DSH 设置页与面板改的是同一处。

- 备选：默认关。否决——等于没做，用户还得记得打开。

### D7 与官方并存：靠 `/health` 天然去重，不争优先级

不检测官方行的存在、也不改它的配置。它若先拉起，我们探测通过即采纳并把来源标为外部；反之亦然。

## Risks / Trade-offs

- **[冷启动窗口期没有记忆]** → 这是上游同样接受的语义（「前一两回合没有记忆」）；面板显示「正在后台冷启动」，会话不阻塞。
- **[自愈动了用户的运行环境]** → 只在子系统=控制台时执行；先备份；失败即停并报告；回滚＝用备份原件覆盖回去（一条命令）。
- **[自动启动带来进程副作用]** → 有开关；只在需要记忆时触发；命令与手动按钮完全一致（净化环境、不碰 `profile create`）。
- **[与官方双拉]** → `/health` 先探后动，先到者胜、后到者采纳。
- **[宿主不派发会话事件 ⇒ 静默不生效]** → 面板显示「从未被触发」，用户可据此切回手动或反馈。
- **[PE 头解析异常/误判]** → 只在确认为控制台形态时才替换；任何不确定一律不替换、如实标注。
- **[退避档位不合适]** → 退避只影响频率，不影响规格；档位可后续调整。

## Migration Plan

**先决**：`2026-09-13-hindsight-model-daemon-control` 必须先归档（主 spec 里那条「插件 MUST NOT 自行启动、停止或重启守护进程」必须先被 `REMOVED`），否则主 spec 与本变更的 ADDED 需求自相矛盾。

**实施顺序**：纯函数（PE 子系统解析、退避计时、来源判定）→ 宿主接线（会话事件订阅 + 端点/状态扩展）→ 客户端（开关 + 状态行文案）→ 文档与验收清单 → 全仓库回归 → 真机一次：停掉守护进程 → 触发一次会话 → 观察「后台自动拉起 + 无控制台窗口 + 来源=自动 + 四层仍 consistent」。

**回滚**：关掉 `autoStart` 即退回手动语义（无需回滚代码）；若要撤销自愈，用 `pythonw.exe.uv-orig-<ts>` 覆盖回 `.venv\Scripts\pythonw.exe`。
