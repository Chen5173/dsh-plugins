## MODIFIED Requirements

### Requirement: 可回退状态是派生判定且防误触

系统 SHALL 仅在“可回退”时让 `Esc` 执行回退：可回退 = 当前会话 running（可停止），或尾部**不是自然结束**（即尾部非 `settled`——含被打断的 `interrupted` 回复、状态无法识别的 assistant 回复、或刚发出的尚未收到回复的 user 提问）且输入框草稿为空。自然正常结束的回合 MUST NOT 可回退；草稿被编辑、发送了新消息、切换了会话、有弹层/菜单/输入补全打开、输入法组合中、或焦点在外部文本框时，系统 MUST 不接管 `Esc`（把该键让给核心“关闭弹层”等既有行为）。

#### Scenario: 自然正常结束的回合不可回退

- **WHEN** 当前回合已自然正常结束（尾部是 settled 的 assistant 回复），用户按一次或两次 `Esc`
- **THEN** 不停止、不回退、不出现任何提示，编辑器与光标行为与未安装本插件时一致

#### Scenario: 被打断或不完整回合可进入可回退态

- **WHEN** 当前回合尾部是被打断的 `interrupted` 回复、或状态无法识别的 assistant 回复、或是刚发出尚未收到回复的 user 提问，且输入框草稿为空
- **THEN** 该会话处于可回退态，按 `Esc` 可进入相应处理（运行态先停止、非运行态先武装）

#### Scenario: 编辑草稿后解除可回退

- **WHEN** 会话处于已停止可回退状态，用户在输入框输入了新草稿后按 `Esc`
- **THEN** 不回退本轮，不覆盖正在编辑的新草稿

#### Scenario: 弹层打开时 Esc 先关弹层

- **WHEN** 有命令菜单、设置面板、图册等弹层/菜单打开，用户按 `Esc`
- **THEN** 先关闭该弹层，不触发停止或回退；弹层关闭后再按 `Esc` 才回到停止/回退语义

#### Scenario: IME 组合或外部文本框焦点不触发

- **WHEN** 输入法组合过程中、或焦点在非 composer 的文本框（如侧栏搜索框）内，用户按 `Esc`
- **THEN** 不发生停止或回退

### Requirement: Esc 二次回退撤销整轮并重开分支会话

系统 SHALL 在“可回退”状态下，用户**连续按第二次** `Esc` 时撤销刚被停止（或刚发出）的整轮：取消并清掉排队消息（若在运行），定位“本轮开始前”的上一完整回合边界，fork 出一个新分支会话并保留原标题，**按当前旧会话处置策略处理原会话（默认：归档原会话）**，打开分支会话，并把被撤销的问题文本（尽力含图片）还原到分支的输入框。回退 MUST 只影响当前会话与其派生分支，MUST NOT 破坏其它会话或已有日志。第一次 `Esc`（无论运行态或非运行态）MUST NOT 立即回退：运行态第一次=停止，非运行态第一次=武装并提示“再按一次 Esc 回退本轮”，第二次才真正回退。

#### Scenario: 停止后二次 Esc 完成回退

- **WHEN** 会话正在生成，用户按一次 `Esc` 停止，再按一次 `Esc`
- **THEN** 该整轮（含半截回复、工具消息与排队消息）从当前可见会话中消失：fork 出新分支并打开，原会话被**按当前处置策略处理**（归档模式=归档并从主列表消失，删除模式=被真删），标题与原会话一致（无“副本”后缀），输入框还原了被撤销的问题文本

#### Scenario: 非运行态第一次 Esc 仅武装提示

- **WHEN** 非运行态（尾部非 settled 且草稿为空）的用户按一次 `Esc`
- **THEN** 不立即回退，仅进入武装态并出现“再按一次 Esc 回退本轮”提示

#### Scenario: 非运行态第二次 Esc 完成回退

- **WHEN** 非运行态用户已按过一次 `Esc`（处于武装态）后，再按一次 `Esc`
- **THEN** 该整轮被撤销并重开分支会话，行为与“停止后二次 Esc”一致

#### Scenario: 回退后从上一完整回合继续

- **WHEN** 用户改写被还原的问题文本后发送
- **THEN** 模型上下文从上一完整回合开始，不重复已被撤销回合的内容

#### Scenario: 带图片的问题尽力还原图片

- **WHEN** 被撤销的用户问题包含图片，且图片可读取
- **THEN** 输入框还原该问题文本并尽力还原图片（缩略图出现）；个别图片读取失败时降级为纯文本，不报错、不阻塞回退

#### Scenario: 原会话可恢复（非破坏性）

- **WHEN** 一次回退完成（原会话已被归档）
- **THEN** 原会话仍可从归档/隐藏视图找到并恢复，日志零丢失

## ADDED Requirements

### Requirement: 「再按 Esc 回退」提示只在用户主动停止后出现

系统 SHALL 仅在用户**本会话内主动触发过一次停止**（工具栏 Stop，或未竞态抢占的 Esc 停止）之后，才在尾部非正常结束且草稿为空时显示「再按 Esc 回退本轮」提示；首次挂载/切换进入一个**本身就非正常结束**的会话（例如上一轮因 429 配额失败、或被打断但仍未重试的历史会话）MUST NOT 弹出该提示。判定以「本会话内 running 是否发生过 true→false 下降沿」为准：切进已失败会话时 running 全程为 false、无下降沿，故不提示。

#### Scenario: 切进已失败的会话不提示

- **WHEN** 用户切换进入一个尾部非正常结束（如上一轮 429 失败的）会话，且未在本会话内做过任何停止操作
- **THEN** 不出现「再按 Esc 回退本轮」提示；仅当用户随后亲手按 `Esc` 或工具栏 Stop 触发停止后，才显示该提示

#### Scenario: 本会话内工具栏 Stop 后提示一次

- **WHEN** 用户在本会话内用工具栏 Stop 停止一次（running 由 true 变为 false），尾部变为非正常结束且草稿为空
- **THEN** 出现「再按 Esc 回退本轮」提示一次（每回合至多一次）
