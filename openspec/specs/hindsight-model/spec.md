# hindsight-model Specification

## Purpose

让用户在 DSH 设置页里查看并修改 Hindsight 守护进程的推理模型配置，并且能对「这次修改到底生效了没有」拿到一个可断言的结论 —— 因为该守护进程既无热加载、又会被外层环境变量在每次启动时静默改写权威配置文件。

## Requirements

### Requirement: 设置页提供 Hindsight 模型面板

系统 SHALL 在设置页提供一个「Hindsight 模型」面板，展示四层事实：① 权威配置文件（profile `.env`）的落盘值；② 运行中守护进程实际生效的值；③ 会覆盖权威文件的外层冲突源；④ 「是否已生效」的判据。当面板所依赖的宿主端点不可达时，面板 SHALL 渲染明确的不可用说明，MUST NOT 呈现空白面板、静默失败或未捕获的报错。

#### Scenario: 打开设置页看到面板

- **WHEN** 用户在 web 形态下打开设置页
- **THEN** 出现「Hindsight 模型」面板，且四层事实各自可见（不可得的那一层标为未知，见后续需求）

#### Scenario: 宿主端点不可达

- **WHEN** 面板加载时宿主端点不可达或返回错误
- **THEN** 面板显示明确的不可用说明（含失败原因），同时不抛出未捕获异常、不显示成"四层皆空"的假状态

### Requirement: 四层取值必须分别呈现并标出彼此差异

系统 SHALL 分别呈现四层取值，并 MUST 在同一视图内标出层与层之间的差异，而不是只显示「当前值」一个数字。当外层冲突源与落盘值不一致时，系统 MUST 把冲突的键逐个列出。当落盘值新于运行中进程的启动时间时，系统 MUST NOT 仅凭该时序关系宣称「尚未生效」，MUST 与该进程实际读到的取值比对后再给结论（见「生效验证必须给出可断言的结论」）。

#### Scenario: 文件比进程的启动时间新

- **WHEN** 权威配置文件的修改时间晚于运行中守护进程的启动时间
- **THEN** 面板不因该时序关系单独标注「尚未生效」；结论来自与运行中取值的比对，必要时补充「文件在进程启动后被重写过」

#### Scenario: 外层环境变量与落盘值冲突

- **WHEN** 外层存在与权威文件同名的配置键且取值不同
- **THEN** 冲突源逐键列出（含取自用户级环境与取自宿主进程环境的分别标注），并标明它会在下次启动时覆盖权威文件

#### Scenario: 各层一致

- **WHEN** 权威文件、运行中进程、外层环境三者的取值一致
- **THEN** 面板不产生任何冲突或未生效提示

### Requirement: 「未设」与「被覆盖」必须是不同状态

系统 SHALL 区分「该键在权威文件中未设置」与「该键已设置但被外层冲突源盖过」两种状态：前者 MUST 提示将回落到哪个内置默认值，后者 MUST 用独立标记呈现并同时给出实际生效值。二者 MUST NOT 合并为同一种「空值」表现。

#### Scenario: 键未设置

- **WHEN** 某配置键在权威文件中不存在
- **THEN** 该字段标为未设置，并显示它会回落到的默认取值（若存在内置默认）

#### Scenario: 键被外层覆盖

- **WHEN** 某配置键在权威文件中存在，但外层冲突源有同名异值键
- **THEN** 该字段用「被覆盖」标记，并同时显示落盘值与实际生效值

### Requirement: 配置写入是行级增改且可回滚

系统 SHALL 以「按 `KEY=VALUE` 解析、只改动命中键所在行」的方式更新权威配置文件；未涉及的行的内容与顺序 MUST 逐字节保持不变。配置文件中不存在的键 MUST 追加到文件末尾。每次写入前 MUST 生成带时间戳的备份，写入失败 MUST 从该备份回滚。系统 MUST NOT 调用会整体重写该文件的官方 profile 创建路径。

#### Scenario: 只改命中键

- **WHEN** 用户修改一个已存在的键并保存
- **THEN** 只有该键所在行变化，其余行（含注释行、模板行、顺序、行尾风格）保持逐字节不变

#### Scenario: 写入新键

- **WHEN** 用户为一个权威文件中不存在的键赋值并保存
- **THEN** 该键以 `KEY=VALUE` 形式追加到文件末尾，既有内容不变

#### Scenario: 写入失败回滚

- **WHEN** 写入过程中发生失败（磁盘、权限、进程中断）
- **THEN** 文件恢复到写入前的备份内容，且面板显示失败原因，不留下半写状态

#### Scenario: 不触发整体重写

- **WHEN** 用户保存任意一组配置
- **THEN** 权威文件中与本次无关的键既不丢失也不被重排

### Requirement: 冲突源检测与处置边界

系统 SHALL 检测并分别列出两类外层冲突源：操作系统用户级环境变量、以及宿主进程自身的环境变量。系统 MUST NOT 尝试修改宿主进程的环境变量，且 MUST 在面板上明确声明这一边界（告知用户该值来自启动宿主的上层环境，需由用户自行清理）。

#### Scenario: 两类冲突源分别列出

- **WHEN** 面板加载冲突源信息
- **THEN** 用户级环境变量与宿主进程环境变量分别成组列出，各自标明键名与取值来源，且不混为一份清单

#### Scenario: 声明不可清理的边界

- **WHEN** 宿主进程环境变量中存在冲突键
- **THEN** 面板说明该冲突无法由本插件清除，并给出用户自行处理的指引

### Requirement: 清理用户级冲突键需先导出备份并二次确认

当用户要求清理操作系统用户级的冲突键时，系统 SHALL 先把这些键（含名与值）导出为带时间戳的备份文件，再执行删除；执行前 MUST 有二次确认，用户取消时 MUST NOT 删除任何键。清理范围 MUST 只限会覆盖权威文件的那些键。

#### Scenario: 先备份再删除

- **WHEN** 用户确认清理用户级冲突键
- **THEN** 备份文件先写入并成功，随后才执行删除；面板显示备份文件路径

#### Scenario: 用户取消

- **WHEN** 用户在二次确认时取消
- **THEN** 不删除任何环境变量，也不生成备份文件

#### Scenario: 只动冲突键

- **WHEN** 执行清理
- **THEN** 用户级环境中与该配置无关的键一律不变

### Requirement: 从 DSH 读取只预填表单，不写盘

系统 SHALL 提供「从 DSH 读取」，把 DSH 当前的默认模型选择及其提供方路由的端点信息预填进表单，且 MUST NOT 在读取过程中写入任何配置文件。若某个字段读取失败，系统 MUST 只把该字段留空并说明原因，其余字段照常预填。

#### Scenario: 预填不写盘

- **WHEN** 用户点击「从 DSH 读取」
- **THEN** 表单被预填，而权威配置文件的修改时间与内容均不变化

#### Scenario: 单项读取失败

- **WHEN** 端点信息或凭据来源无法解析
- **THEN** 相应字段留空并标注原因，其余字段仍被预填

### Requirement: DSH 的 API 密钥明文不出宿主进程

系统 MUST NOT 把 DSH 侧解析出的 API 密钥明文回传给浏览器：表单对密钥只显示「有值 / 长度 / 来源标识」。系统 SHALL 提供「保存时使用 DSH 的这把密钥」选项，勾选后由宿主半在保存时解析并使用该密钥，整个过程 MUST NOT 让明文出现在任何发往浏览器的响应、日志或诊断中。

#### Scenario: 密钥不以明文回传

- **WHEN** 用户点击「从 DSH 读取」且 DSH 侧存在可用密钥
- **THEN** 表单只显示该密钥的存在性、长度与来源标识，任何浏览器侧响应中都不含明文

#### Scenario: 勾选后由宿主半使用

- **WHEN** 用户勾选「保存时使用 DSH 的这把密钥」并保存
- **THEN** 权威文件被写入由宿主半解析出的密钥值，而浏览器侧全程未见明文

### Requirement: 生效验证必须给出可断言的结论

系统 SHALL 提供独立于写入的「验证」动作，回答「当前生效的是哪套值」，且 MUST 说明本次结论所依据的证据。判定 SHALL 以「权威文件的推理三件套（provider / model / 端点）与运行中进程实际读到的三件套是否一致」为准：一致 MUST 判定为已生效；不一致 MUST 判定为未生效并逐个列出不一致的字段及两侧取值。**仅当运行中进程的实际取值不可得**（启动日志缺少配置读取行，或守护进程未运行）时，系统 SHALL 回退到「守护进程启动时间晚于权威配置文件修改时间」这一时序判据；该时序判据不成立时 MUST NOT 判定为已生效。

> 为什么不是单一时序判据：上游守护进程的启动路径本身会回写这个文件（`_register_profile()` → `create_profile()` 整体重写），使文件修改时间落在进程启动**之后**。实测本机就是这种状态（文件 18:56:29、进程 18:55:46，而两者取值完全一致）。只按时间判定，会对一个完全健康的配置长期误报「未生效」。

#### Scenario: 文件与进程取值一致

- **WHEN** 权威文件的推理三件套与运行中进程启动日志里的三件套相同
- **THEN** 验证结论为「已生效」，并给出该三件套与启动日志中的连通性结论

#### Scenario: 文件与进程取值不一致

- **WHEN** 权威文件的推理三件套与运行中进程实际读到的三件套存在差异
- **THEN** 验证结论为「未生效」，并逐个列出不一致的字段及其「文件值 vs 进程值」

#### Scenario: 文件比进程新但取值一致

- **WHEN** 权威文件的修改时间晚于守护进程的启动时间，而两者取值一致
- **THEN** 验证结论仍为「已生效」，并补充说明文件在进程启动后被重写过（可能只是启动路径把同值写回了一遍）

#### Scenario: 运行中取值不可得时回退到时序判据

- **WHEN** 启动日志缺少配置读取行（或守护进程未运行），无法取得进程的实际取值
- **THEN** 回退到「启动时间晚于文件修改时间」判据：该判据成立时可判定为已生效但 MUST 明示无法确认进程实际读到的值；该判据不成立时 MUST 判定为未生效并说明当前跑的是重启前的配置

### Requirement: 守护进程未运行时未知即未知

当守护进程未运行时，系统 MUST 把「运行中实际生效值」与「生效判据」两层标为未知，MUST NOT 把历史日志或落盘值当作现状呈现。

#### Scenario: 守护进程未运行

- **WHEN** 守护进程未在监听配置端口
- **THEN** 相关两层显示为未知，且不展示任何过期取值或成功结论

### Requirement: 敏感值不得进入日志或诊断

系统 MUST NOT 把 API 密钥等敏感值写入日志、诊断快照或任何回传内容；对敏感键只允许暴露其存在性、长度与来源标识。备份文件路径可以被展示，但备份内容 MUST NOT 被回传。

#### Scenario: 诊断只含非敏感元信息

- **WHEN** 面板请求状态或诊断信息
- **THEN** 响应中敏感键只出现存在性、长度与来源标识，不含取值

#### Scenario: 备份内容不回传

- **WHEN** 面板展示备份相关信息
- **THEN** 只出现备份文件路径与时间，不出现备份文件内的键值内容

### Requirement: 核心能力缺失时降级并说明缺口

当所需的宿主侧能力或本机 Hindsight 配置缺失时，系统 SHALL 降级而不是报错，且 MUST 明确指出缺的是哪一项。

#### Scenario: 缺少读取 DSH 模型所需的服务

- **WHEN** 读取默认模型选择、提供方目录或凭据解析所需的服务之一不存在
- **THEN** 「从 DSH 读取」被禁用，并列出缺失的能力项，其余四层展示照常工作

#### Scenario: 本机 Hindsight 配置缺失

- **WHEN** 读不到 Hindsight 的本机配置（守护进程端口或运行目录未知）
- **THEN** 只禁用重启命令区并说明原因，其余层与写入功能照常

### Requirement: 面板可启停守护进程，且启停必须净化子进程环境

系统 SHALL 允许用户从面板直接启动、停止与重启 Hindsight 守护进程，并 MUST 在同一视图展示其当前状态：是否运行中、进程标识、端口、进程启动时间、以及健康检查结果。启停所用的 profile 名与运行目录 MUST 取自本机 Hindsight 配置而非硬编码。**系统 MUST 在执行任何启动动作时净化子进程的环境变量**，清除会覆盖权威文件的外层同名键，使权威文件成为唯一真源；MUST NOT 让外层取值经启动路径被写回权威文件。停止与重启 MUST 在动作前取得用户确认，用户取消时 MUST NOT 执行任何进程动作。当守护进程本就未运行时，「停止」MUST 视为幂等成功并如实说明，MUST NOT 报错。系统 SHALL 仍展示将实际执行的命令文本，以便用户复制与审计。当本机配置不可读或无法生成启停命令时，系统 MUST 禁用该区块并说明缺口，MUST NOT 影响四层展示、写入与验证。系统 MUST NOT 因启停动作改动权威文件以外的任何配置。

#### Scenario: 启动

- **WHEN** 守护进程未运行且用户点「启动」
- **THEN** 守护进程被启动，面板状态更新为运行中并给出其进程标识与端口

#### Scenario: 启动时净化环境

- **WHEN** 系统执行启动动作
- **THEN** 子进程环境中不含会覆盖权威文件的外层同名键，因此权威文件的取值不会被外层值静默改写

#### Scenario: 停止与重启需确认

- **WHEN** 用户点「停止」或「重启」
- **THEN** 先出现确认；用户取消时守护进程的启动状态与进程标识都不发生改变

#### Scenario: 对已停止的守护进程点停止

- **WHEN** 守护进程本就未运行而用户点「停止」
- **THEN** 该动作按幂等成功处理并如实说明它本就未运行，不产生错误提示

#### Scenario: 重启等于先停后起

- **WHEN** 用户确认「重启」
- **THEN** 系统先停止、待端口释放后再启动，最终状态为运行中且进程标识已更新

#### Scenario: 展示将执行的命令

- **WHEN** 面板可读到本机 Hindsight 配置
- **THEN** 面板展示将实际执行的命令文本，其中的 profile 名与运行目录与该配置一致

#### Scenario: 本机配置不可读时禁用该区块

- **WHEN** 读不到本机 Hindsight 配置或无法生成启停命令
- **THEN** 启停区块被禁用并说明缺什么，而四层展示、写入与验证照常可用
